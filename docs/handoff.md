# 零壹 SaaS 平台 Prototype 交接文件

Nov 5, 2026

## 背景與目標

零壹要做三個網站，讓經銷商與終端客戶透過平台管理 Google Workspace（GWS）與 Google Cloud（GCP）。第一步是先做出可點擊的 Prototype，給使用者確認需求。

- 三個網站：管理端（零壹內部使用）、經銷商端、終端客戶端，三個都需要權限控管。
- 目前整合 GWS 與 GCP，之後會支援其他品牌與產品。
- 老闆的期限是 2026 年 12 月底前：零壹平台 GWS 上線、GCP 可以看到流量與用量、三個平台的 Prototype 完成。
- 本文件的範圍是 Prototype 的前端畫面，全部使用假資料。後端由 Terry 開發，API 格式尚未提供，之後再串接。
- 開發順序：先做管理端，再做經銷商端與終端客戶端。
- 介面語言：繁體中文。

## 角色與權限

三個網站共用同一套權限模型。原則是「零壹只開第一個帳號，其他由對方自己管」。

**組織與資料範圍**

- 零壹內部使用者：可以看到所有經銷商與客戶。
- 經銷商使用者：只能看到自己名下的客戶。
- 客戶使用者：只能看到自己公司。
- 資料範圍永遠由帳號所屬的組織決定，不可以只靠前端隱藏。後端必須再檢查一次，Prototype 只需模擬。

**帳號建立流程**

1. 零壹建立經銷商或客戶時，同時建立第一個「組織管理員」帳號。
2. 組織管理員登入後，在「使用者」和「角色管理」自己建立其他帳號與角色。
3. 新角色的權限以「資源等級」設定，每個資源（客戶、訂閱、執行單、GCP 用量、帳號、系統日誌等）選「禁止、唯讀、可編輯」。

**原先羽昇平台的 8 個角色（參考）**

- 後台管理員、財務、銷售
- 工作人員：產品管理、技術、業務、業務 PickUp
- 組織管理員

Prototype 的「角色管理」頁先用上面的名稱當範例資料。預設內部角色清單以後再跟使用者確認。

**還沒決定（請標記在畫面上，不要自己決定）**

- 「帳單」是不是獨立的權限資源（這也就是「經銷商要不要分 Billing」問題的答案，待問 Connie）。

**網域檢查規則**：格式用 `^([a-z0-9]([a-z0-9-]*[a-z0-9])?\.)+[a-z]{2,}$`；系統內不重複；Google 網域驗證在建立後才檢查。輸入正確且不重複才能按「建立」。

## 技術方向與做法原則

Prototype 階段的目標是「讓使用者點得動、看得懂」，之後要能接上 Terry 的後端，所以結構要一開始就分層。

- **語言與框架**：TypeScript 加 React（或 Next.js）。這是建議，如果 Terry 的部署方式（例如 Cloudflare Workers）有限制，再調整。
- **三個網站共用元件**：版型、表格、篩選列、狀態標籤、表單都抽成共用元件資料夾。管理端先做，經銷商端與客戶端再重用，只改選單和權限。
- **資料層分離**：假資料集中在一個資料層，頁面只透過函式取得資料。之後換成真的 API 呼叫時，頁面不用動。
- **權限**：Prototype 可以用一個「目前登入身分」切換器模擬不同角色看到的畫面。真正的權限檢查一定要在後端做，不能只靠前端隱藏按鈕。
- **寫入動作的假行為**：開立執行單、送出 Google、重送等動作，只在記憶體中改狀態並顯示提示，不需要永久保存。
- **範圍限制**：Prototype 不碰真實的 Google 帳號，不連線到任何 Google API。
- **之後上線需要的技術提醒**：GWS 排程需要真的排程器與失敗重試；GWS 整合預計用 Admin SDK 與 Cloud Channel API（待 Ray、Terry 確認）；GCP 費用預計從 Billing 匯出（BigQuery）取得。這些不在 Prototype 範圍內，只是讓 Claude Code 了解方向。
- **程式碼品質**：每頁寫完自己開起來看過（桌面 1440 寬，也要確認窄螢幕不會破版）。
